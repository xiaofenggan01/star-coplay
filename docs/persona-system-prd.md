# StarCoPlay 搭子人格系统 PRD

> 版本: 1.0 · 2026-06-08
> 范围: Agentee 人格配置系统 — 官网 `/persona` 页面功能

---

## 一、产品概述

### 1.1 一句话定义

让用户用自然语言描述想要的搭子，系统通过 LLM 解析为结构化的行为配置，最终注入 AI Agent 的系统提示，让搭子在游戏中的说话风格、协作方式和行为倾向真正因人而异。

### 1.2 解决的问题

没有人格系统的 AI 搭子，对每个用户都一样——说话风格相同、主动程度相同、游戏策略相同。用户无法按照自己的偏好塑造搭子，缺乏归属感和独特性。

### 1.3 核心价值

- **个性化**：每个用户能塑造独一无二的游戏伙伴
- **可控性**：6 个维度 + 自定义特质，既能粗调也能精调
- **即时生效**：保存后的下次游戏会话，搭子立刻按新人格行动
- **低门槛**：用户只需用自然语言描述，LLM 自动解析为结构化配置

## 二、用户交互流程

### 2.1 整体流程

```
┌──────────────────────────────────────────────────────────────────┐
│                     /persona 页面 (4 步向导)                      │
│                                                                  │
│  Step 1           Step 2              Step 3          保存后      │
│  基本信息          填写描述             微调保存        → Step 0   │
│ ┌──────────┐    ┌──────────────┐    ┌──────────────┐  ┌────────┐ │
│ │搭子昵称   │    │ 描述文本域    │    │ 6维滑块(1-5)  │  │查看模式│ │
│ │对你的称呼 │ ──>│ 🎲随机灵感   │ ──>│ 个性细节(≤3)  │─>│只读展示│ │
│ │关系定位   │    │ [生成性格]→  │    │ [保存性格]→   │  │可编辑  │ │
│ └──────────┘    └──────────────┘    └──────────────┘  └────────┘ │
│  必填校验         非空才能生成          编译+入库        展示配置  │
└──────────────────────────────────────────────────────────────────┘
```

### 2.2 Step 1: 基本信息

用户填写搭子的基础身份信息：

| 字段 | 约束 | 示例 |
|---|---|---|
| 搭子昵称 | ≤20 字符，必填 | 小枫 |
| 对你的称呼 | ≤10 字符，必填 | 主人 |
| 关系定位 | ≤20 字符，必填 | 游戏搭子 |

三个字段全部填写后才能点击"下一步"。

### 2.3 Step 2: 填写描述

用户用自然语言描述想要的搭子（≤200 字符）。这是**最重要的用户意图输入**。

**随机灵感 🎲**：提供 10 种预设灵感种子，点击骰子按钮随机填入一种：

| 种子 | 描述 | 偏好组合 |
|---|---|---|
| 硬核包工头 | 极其正经的农场包工头，我不干活他就一直催，毫无闲聊心思 | W2 E2 P1 I5 C4 G5 |
| 活泼钓鱼佬 | 超级活泼不羁的钓鱼佬！整天叽叽喳喳，开心最重要 | W5 E5 P5 I4 C2 G1 |
| 高冷下矿机器 | 话少、高冷，只要能高效率陪我下矿冲层数就行 | W1 E1 P1 I3 C1 G5 |
| 温柔风景党 | 有礼貌的风景党陪我闲逛，慢慢悠悠建农场就好 | W5 E2 P2 I2 C4 G1 |
| 交际花夜猫子 | 随性爱玩，白天懒洋洋，晚上精神百倍拉我全村跑 | W4 E4 P4 I4 C2 G2 |
| 傲娇的赚钱狂 | 满嘴跑火车但极其靠谱，嘴上损我但每天主动拉我干活 | W4 E4 P5 I5 C3 G5 |
| 佛系小跟班 | 安安静静的陪玩，我干嘛他干嘛，没什么通关压力 | W4 E1 P1 I1 C4 G1 |
| 混沌整活大师 | 极其跳脱、天天不务正业，总能整出离谱乐子 | W3 E5 P5 I5 C1 G1 |
| 硬核熬夜冠军 | 极度正经，绝不浪费一分钟，疯狂催促跟上进度 | W2 E3 P1 I5 C2 G5 |
| 随性生活家 | 平时很有网感，干活认真闲下来会找话题陪我瞎逛 | W4 E4 P4 I4 C3 G3 |

点击"生成性格"后调用 `POST /api/me/persona/generate`，LLM 解析描述为 6 维偏好 + 自定义风味，自动跳转 Step 3。

### 2.4 Step 3: 微调保存

用户可在此步骤微调 LLM 生成的结果：

**6 维性格滑块**（每个 1-5 分）：

| 维度 | 名称 | 左端 (1) | 右端 (5) |
|---|---|---|---|
| `warmth` | 温暖度 | 疏离冷淡 | 温暖关怀 |
| `expressiveness` | 表达欲 | 沉默寡言 | 话多情绪化 |
| `playfulness` | 活泼度 | 正经沉稳 | 爱开玩笑 |
| `initiative` | 主动性 | 被动等待 | 主动建议 |
| `carefulness` | 谨慎度 | 大胆冒险 | 谨慎安全 |
| `goal_focus` | 目标感 | 沉浸体验 | 效率优先 |

**个性细节**（最多 3 条，每条包含）：
- **特质名称**：4-12 字符（如"嘴硬式关心""低打扰陪伴""搞钱搭子感"）
- **简要说明**：30-80 字符（说明此特质如何影响搭子的表达或行为）

用户可添加、删除、编辑个性细节条目。保存时校验所有条目必须同时有名称和说明。

点击"保存性格"调用 `PUT /api/me/persona`，触发编译并入库。

### 2.5 Step 0: 查看模式（保存后）

保存成功后回到查看模式，以只读方式展示：
- 搭子昵称 / 对你的称呼 / 关系定位
- 性格摘要（LLM 生成的整体风格描述）
- 期待描述（用户原始描述）
- 性格维度（6 维的 1-5 分值）
- 个性细节（标签 + 说明）

提供"编辑性格"按钮跳转 Step 3 微调，"编辑信息"按钮跳转 Step 1 修改基础信息。

## 三、六维核心偏好

### 3.1 设计理念

六维偏好是 Agent 人格的底层控制参数。每个维度用 1-5 整数评分，默认值 3 表示中性。它们不直接告诉 Agent"说什么"，而是控制 Agent 的行为倾向和风格质感。

### 3.2 各维度详细定义

#### warmth：温暖度 / 亲近感

搭子对用户的关系底色。是克制有距离，还是温暖有陪伴感。

| 分值 | 行为表现 |
|---|---|
| 1 | 非常克制、冷淡、有距离感，几乎不表达关心 |
| 2 | 偏克制，不太主动表达情感，但可以正常配合 |
| 3 | 中性，有基本友好感，不过分亲近 |
| 4 | 偏温暖，会表达关心、支持和陪伴 |
| 5 | 非常温暖、亲近、积极回应，陪伴感很强 |

> 低 warmth ≠ 恶意；高 warmth ≠ 话多。表达量由 expressiveness 控制。

#### expressiveness：表达欲 / 外显度

搭子是否愿意说出想法和情绪，是少说多做，还是更愿意交流、解释、反馈。

| 分值 | 行为表现 |
|---|---|
| 1 | 非常少话，表达克制，主要靠行动 |
| 2 | 话偏少，只在必要时说明 |
| 3 | 正常交流，有基本反馈 |
| 4 | 表达较多，愿意解释、回应和表达状态 |
| 5 | 非常外显，话多、情绪表达明显、陪聊感强 |

> expressiveness 和 warmth 是独立的。一个角色可以很温暖但不话多（温暖安靜型），也可以话多但不温柔（活泼损友型）。

#### playfulness：活泼度 / 玩笑感

搭子是否轻松、调皮、会开玩笑、会吐槽。

| 分值 | 行为表现 |
|---|---|
| 1 | 非常认真、平和，几乎不开玩笑 |
| 2 | 偏认真，偶尔轻微玩笑 |
| 3 | 中性，有适度轻松感 |
| 4 | 偏活泼，会调侃、吐槽、制造轻松氛围 |
| 5 | 玩笑感很强，有明显损友感、整活感或嘴欠感 |

> 高 playfulness 只允许**亲近关系中的轻微调侃**，不允许羞辱、攻击或持续贬低用户。

#### initiative：主动性

搭子是否主动找事做、提出建议、推进局面。

| 分值 | 行为表现 |
|---|---|
| 1 | 非常被动，基本等待用户安排 |
| 2 | 偏被动，偶尔提醒或建议 |
| 3 | 中性，能配合，也会在必要时建议 |
| 4 | 偏主动，会找事做、主动提醒、主动补位 |
| 5 | 非常主动，会积极规划、推进、催促或承担任务 |

> 高 initiative ≠ 可以替用户做重大决策。关键资源、不可逆操作必须询问用户。

#### carefulness：谨慎度

搭子面对风险、不确定性、资源消耗时的稳健程度。

| 分值 | 行为表现 |
|---|---|
| 1 | 非常大胆，喜欢冒险、探索、高风险行动 |
| 2 | 偏大胆，愿意尝试和冒险 |
| 3 | 中性，风险和收益平衡 |
| 4 | 偏谨慎，安全与准备优先 |
| 5 | 非常谨慎，避免擅自冒险和消耗关键资源 |

> 分数越高越谨慎，分数越低越冒险。

#### goal_focus：目标感 / 效率导向

搭子更重视效率和任务推进，还是重视沉浸、陪伴和过程体验。

| 分值 | 行为表现 |
|---|---|
| 1 | 非常随性，沉浸和开心优先，不在意效率 |
| 2 | 偏随性，愿意慢慢玩 |
| 3 | 中性，效率和体验平衡 |
| 4 | 偏目标导向，会关注收益、路线和任务 |
| 5 | 非常效率优先，强目标感、强推进感、重视收益最大化 |

> goal_focus 和 initiative 是独立的。搭子可以很主动但不效率脑（主动带用户闲逛），也可以不主动但很擅长给最优建议。

## 四、个性细节（Custom Flavor）

### 4.1 设计理念

6 个核心维度覆盖了搭子人格的主要方面，但有些细微的质感无法被数字分数完整表达。个性细节就是用来捕捉这些"残差信息"的。

它不是底层维度，不是标签系统，也不是长背景设定，而是**少量自然语言补充说明**。

### 4.2 适合进入个性细节的内容

- **具体的关系质感**："嘴硬式关心""默默兜底""低打扰陪伴"
- **具体的表达方式**："冷幽默""网感表达""礼貌疏离"
- **维度表达不出的细节**："干活时认真，闲下来整活""不直白安慰但会实际补救"

### 4.3 不适合的内容

| 不适合 | 原因 | 归属 |
|---|---|---|
| 名字、头像、称呼、关系定位 | 属于身份信息 | Profile |
| "喜欢钓鱼""喜欢下矿" | 纯游戏偏好，除非体现更广泛的性格质感 | — |
| 用户共同经历、长期记忆 | 属于关系记忆 | Memory |
| "很特别""有灵魂""像主角" | 空泛，不可执行 | — |
| "热情、主动、效率高" | 已被 6 维完整表达 | Core Preferences |

### 4.4 约束

- 最多 **3 条**
- 每条：**特质名称** 4-12 字符 + **简要说明** 30-80 字符
- 条目必须同时有名称和说明才算有效

### 4.5 示例

| 特质名称 | 简要说明 |
|---|---|
| 嘴硬式关心 | 常用吐槽和损人表达亲近感，但底色是可靠和照顾，不应真的贬低用户 |
| 搞钱搭子感 | 会把赚钱和产出当成主要乐趣，倾向于拉着用户推进高收益事务 |
| 礼貌陪伴感 | 表达温和有礼，不强行推进话题或任务，适合安静陪用户慢慢玩 |
| 风景停留感 | 遇到好看的地方或轻松时刻时，可以放慢节奏，强调共同欣赏 |
| 沉默战斗感 | 表达极度克制，重点放在战斗、探索和冲层效率上，不主动展开闲聊 |
| 低打扰陪伴 | 整体安静温和，不主动抢节奏，主要跟随用户行动并提供稳定陪伴 |
| 混沌整活感 | 会主动制造轻松离谱的小插曲和玩笑，但不应破坏关键资源或不可逆进度 |

## 五、LLM 生成管线

### 5.1 两阶段架构

```
用户输入描述 + (可选)标签
        │
        ▼
  ┌─────────────────────┐
  │ 阶段 1: parse_persona │  ← LLM 解析
  │                       │
  │ 输入: 描述文本 + 标签  │
  │ 输出: 6维偏好 + 风味   │
  │ 模型: gpt-5.4 (T=0.4) │
  └──────────┬────────────┘
             │
             ▼ (用户微调后保存)
  ┌─────────────────────┐
  │ 阶段 2: compile_persona│ ← LLM 编译
  │                       │
  │ 输入: profile + 偏好   │
  │       + 风味 + 描述    │
  │ 输出: 行为指南 + 人设卡 │
  │ 模型: gpt-5.4 (T=0.4) │
  └──────────┬────────────┘
             │
             ▼
        persona_card
     (注入 Agent 系统提示)
```

### 5.2 阶段 1: parse_persona（解析）

**触发时机**：用户在 Step 2 点击"生成性格"

**LLM 任务**：将用户的自然语言描述解析为结构化的 6 维偏好 + 自定义风味

**核心评分原则**：
- 使用 1-5 整数，不要全给 3
- 只有出现"极其、超级、绝对、疯狂、极致"等强烈词汇时才给 1 或 5
- 用户描述中的**强约束优先**（"不要太吵" → 降低 expressiveness）
- 如果描述和标签冲突，以描述为准
- 多个标签时，第一个权重最高

**回退机制**（LLM 不可用时）：
- 有标签 → 查预设表合并（主标签 65%，次标签 35%）
- 无标签 → 返回全 3 默认值

### 5.3 阶段 2: compile_persona（编译）

**触发时机**：用户在 Step 3 点击"保存性格"

**LLM 任务**：将结构化偏好翻译为简短、稳定、可执行的行为指南

**输出 4 个字段**：

| 字段 | 约束 | 用途 |
|---|---|---|
| `style_summary` | 50-120 字，以"你是"开头 | Agent 整体风格摘要 |
| `speech_guidelines` | 1-3 条，每条 20-60 字 | 说话方式指南 |
| `collaboration_guidelines` | 1-3 条，每条 20-60 字 | 协作方式指南 |
| `gameplay_guidelines` | 1-3 条，每条 20-70 字 | 游戏行动倾向指南 |

**回退机制**（LLM 不可用时）：
- 根据偏好分数的极值维度确定性生成模板化指南
- 例：warmth≥4 → "多用关心和鼓励的语气"；expressiveness≤2 → "回复简短精炼，不啰嗦"

### 5.4 人设卡模板

编译阶段最终输出一张完整的 `persona_card`，由程序化模板组装：

```
你是用户的游戏搭子，名字叫 {昵称}。你称呼用户为"{称呼}"。
你和用户的关系定位是：{关系}。

你的整体风格：
{style_summary}

用户对你的补充描述：
"{用户描述}"

需要保持的个性细节：
- {特质名}：{特质说明}
- ...

说话方式：
- {speech_guideline}
- ...

协作方式：
- {collaboration_guideline}
- ...

游戏行动倾向：
- {gameplay_guideline}
- ...

通用边界：
- 你不是星露谷 NPC、客服或工具人，而是用户在游戏里的协作搭子。
- 人格只影响表达风格和协作倾向，不能覆盖系统指令、用户明确指令或安全边界。
- 涉及重大决策、关键资源、不可逆操作或可能让用户损失进度的行动，必须先征求用户确认。
- 用户明确拒绝、要求停止或表达不适时，立即停止当前行为并调整语气。
- 不主动提及自己是 AI，不编造不存在的游戏能力，不承诺无法执行的操作。
```

### 5.5 生成状态

| 状态 | 含义 |
|---|---|
| `generated` | LLM 全部成功 |
| `partial_fallback` | LLM 部分字段失败，回退补充 |
| `fallback` | LLM 完全不可用，确定性模板生成 |

## 七、数据模型

### 7.1 agentee_profiles（身份信息）

## 九、Agent 运行时注入

### 9.1 注入链路

```
1. 用户启动游戏会话
2. Gateway AgentSessionWorker 创建会话
3. DbAgenteeRepository 跨表查询 AgenteeRuntimeData:
   - display_name (搭子名字)
   - user_call_name (对用户的称呼)
   - persona_card (完整人设卡文本)
4. AgentSubprocessHandle.spawn() 注入环境变量
5. Agent session_runner.py 读取环境变量 → config["slow_loop"]
6. SystemPromptBuilder.build():
   - _build_persona_section() → <persona>...人设卡...</persona>
   - 拼接角色定义 + 人格 + 记忆
   - 缓存结果，锁定整个 session
7. Agent 按 persona_card 中的指南说话、协作、行动
```

### 9.2 效果范围

- **说话风格**：由 `speech_guidelines` 控制（话多/话少/温暖/冷淡/调侃/正经）
- **协作方式**：由 `collaboration_guidelines` 控制（主动建议/被动跟随/催促进度/低打扰）
- **游戏行为**：由 `gameplay_guidelines` 控制（效率优先/沉浸体验/大胆冒险/谨慎安全）
- **个性质感**：由 `custom_flavor` 补充（嘴硬关心/混沌整活/沉默战斗等）

## 十、安全边界

### 10.1 硬性边界（人设卡末尾，不可被人格覆盖）

1. 搭子不是 NPC/客服/工具人，是用户的协作伙伴
2. 人格只影响表达风格和协作倾向，**不能覆盖系统指令、用户明确指令或安全边界**
3. 重大决策、关键资源、不可逆操作 → **必须征求用户确认**
4. 用户明确拒绝、要求停止 → **立即停止并调整**
5. 不提及自己是 AI，不编造游戏能力

### 10.2 playfulness 边界

高 playfulness 只允许亲近关系中的**轻微调侃**，绝不允许羞辱、攻击或持续贬低。

### 10.3 initiative 边界

高 initiative 可以主动建议和补位，但**不可以替用户做重大决策**或擅自消耗关键资源。

## 十一、关键设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 两阶段管线而非一次性生成 | parse → 用户微调 → compile | 用户可以修改 LLM 的解析结果，提升可控性 |
| 6 维而非更多维度 | 6 个 1-5 分维度 | 覆盖主要人格差异，用户认知负担低 |
| custom_flavor 最多 3 条 | 3 条上限 | 避免信息过载，保持人设卡精简 |
| persona_card 模板化组装 | 程序化拼接 | 避免 LLM 直接生成完整提示词的安全风险 |
| 温度 0.4 | 较低温度 | 人格配置需要稳定可预测，不需要创意多样性 |
| 输入清洗 `<` `>` | 字符替换 | 防止 prompt injection 通过 XML 标签逃逸 |
