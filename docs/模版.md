## 模板使用说明（写完后可删除）

> 📌 **本模板适用于**：跨模块改动 / 涉及外部依赖 / 新增 API / 架构演进 / 工时 ≥ 1 周的功能
>
> 📌 **本模板不适用于**：极小修复、配置改动、纯 bug fix（请直接用 PR 描述即可）

**如何使用本模板**：

1. 按章节顺序填写，每节会先用三块引导你思考：💡 意图 / ❓ 引导问句 / ⚠️ 反例提示
2. 标记 ⭐ 的章节是核心训练点，不允许空着
3. 标记"选填"的章节按文档顶部的判断尺决定（小改动 + 单模块 + 1 天内可省 §8/§10/§12；其他必填全部）
4. 写完后必须勾选末尾的"提交评审前自检清单"全部 8 项

**判断尺**：填本模板前先用 30 秒判断——

- 我做的事情**只影响一个文件 / 一个函数**？→ 不需要本模板，写 PR 描述即可
- 我做的事情**影响多个模块 / 跨服务 / 改动接口**？→ 必填全部带 ⭐ 与"必"的章节
- 我做的事情**涉及上线 / 数据迁移 / 多人协作**？→ 全部章节都填

## 📋 提交评审前自检清单

> 在把文档状态从 🟡 Draft 改为 🔵 In Review **之前**，必须勾选以下全部 8 项。任何一项未通过，请回到对应章节补充。

- **TL;DR ≤ 5 行**，且第一段就讲了"做什么"
- **Goals 可量化**，且 Non-Goals ≥ 2 条
- **方案概述含一张系统图**（不是只有文字）
- **第 5 节代码片段 + 路径 + 目录树总长 ≤ 30%**
- **Alternatives ≥ 2 个**，每个有"为什么没选"
- **Risks ≥ 3 条**诚实负面后果（不是泛泛"考虑了风险"）
- **DoD 可勾选验证**，不是模糊描述
- **陌生人测试**：找 1 个不在本项目的同事读 5 分钟，他能复述结论吗？
