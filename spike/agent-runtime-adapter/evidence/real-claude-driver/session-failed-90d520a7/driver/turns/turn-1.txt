# Turn 1：调查真实 Claude CLI 持续输入协议并形成实验结论

你是执行者。只做调查与受控实验，不实现 Adapter。本轮允许读取仓库文件，并写入：

- `spike/agent-runtime-adapter/evidence/real-claude-driver/turn-1-cli-protocol.md`
- 必要的 `/tmp` 临时文件（结束前清理）

禁止修改 `DRIVER.md`、`DRIVER_STATE.json`、`.driver/`；禁止 commit/push/deploy；禁止访问项目或平台凭据；禁止连接 Gateway、Mod、生产 MCP。

目标：用当前已安装的真实 `claude` CLI 帮助文本与受控实验确认，是否存在**单一 OS 进程**通过 stdin 持续接收至少三条输入并通过 stdout 返回对应结果的受支持非 TTY 协议。重点调查 `--input-format stream-json`、`--output-format stream-json`、`--verbose`、`--include-partial-messages` 等约束。不能使用多次 `claude -p --resume` 冒充单进程持续输入。

要求：

1. 记录 `claude --version`、相关 `claude --help` 原文摘要和精确命令。
2. 设计最小实验：启动一个真实 Claude 进程，向同一 stdin 写入三条合法 stream-json 输入；每条要求简短、禁止工具调用；验证进程 PID 不变、三条输出可关联、stdin 保持开放直到显式 EOF/终止。
3. 使用显式 `--model claude-sonnet-5`。不得输出认证信息或环境秘密。
4. 调查并记录 stream-json 的实际输入 schema、输出事件、ready 判定候选、结束一轮的可靠判定、进程对 EOF/SIGTERM 的行为。
5. 如果三轮实验因协议、认证、网络或费用阻断，记录精确命令、退出码与脱敏错误，给出停止结论；不得用 mock 或多进程代替。
6. 不要长时间悬挂：每次实验设置有界超时并清理子进程。

报告必须区分“帮助文本声明”“实际观察”“仍未知”，并给出下一轮 Adapter 的可实现/不可实现结论。完成后停止。
