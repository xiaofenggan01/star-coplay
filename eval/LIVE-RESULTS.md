## 结果

| 策略 | 通过 | tokens / 场景 | 延迟 |
|---|---|---|---|
| routing | 23/23 | 0 | ~0 ms |
| llm（单次规划） | 23/23 | 713 ± 24 | 913 ± 253 ms |

（多数场景一轮即可完成）。

## 评估集抓到的真实问题

跑通过程中一共改了四轮 prompt / 场景，每一轮都是评估集先报错：

1. **时间被误读**：世界快照只给 `time: 1320`，模型读成 13:20。实际 SDV 的 1320 就是
   13:20——错的是我们场景里把它当成了 22:00。修复：场景时间改成 2000/2200/2330，
   世界快照增加 `time_hhmm`。
2. **“已满足”优先级**：已浇完 + 下雨时，模型拒绝“下雨”而不是返回 satisfied。
   修复：prompt 明确“先判断目标是否已满足”。
3. **睡觉豁免**：23:30 体力 0 时，模型套用“体力不足”拒绝睡觉。修复：prompt 明确
   “睡觉不受体力/时间限制”。
4. **浇水体力阈值**：模型把“体力 < 20”套到浇水上。修复：prompt 区分砍树 20、浇水 10。
5. **自造规则**：22:00 浇水时模型自创“太晚不适合农活”。修复：prompt 禁止发明规则。
6. **数量 0 的语义**：模型认为“0 木头”已满足，规则策略要求澄清。修复：prompt 明确
   “缺失或 0 都表示没说数量，应澄清”。

其中第 1 条是评估集自身的 bug，其余是 prompt 规格不清。修完后三方全绿——这说明
当前场景已经能被清晰规格覆盖，下一步要拉开差距，需要**规格写不出来**的任务
（多目标取舍、长时序、世界状态不确定）。
